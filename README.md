# ハーネスとは何か

AI エージェントの話をしていると、ハーネス (harness) という言葉が出てきます。
モデルそのものではなく、モデルを実際の仕事に使えるようにするための周辺の仕組みを指します。

## モデルは単体では何もできない

LLM が持っている機能は、突き詰めると一つだけです。
テキストを受け取って、続きのテキストを返す。それ以外のことはできません。

ファイルを読むことも、コマンドを実行することも、前回の会話を覚えておくこともできない。
モデルは毎回、渡されたテキストだけを見て応答を返す関数のようなものです。

しかし実際のコーディングエージェントは、リポジトリを探索し、テストを流し、失敗を見て直します。
この差を埋めているのがハーネスです。

## ハーネスが担っていること

ハーネスは、モデルの周りで次のような役割を引き受けます。

**ループを回す**
モデルの応答を読み、ツールを呼べと書いてあれば実際に実行し、その結果をまた入力に加えて次の応答を求める。
これを目的が達成されるまで繰り返します。モデルは一手ずつ判断するだけで、手を進め続けるのはハーネスの仕事です。

**ツールを与える**
ファイル読み書き、コマンド実行、Web 検索といった外界への出口を定義し、モデルに提示します。
モデルができることの上限は、ここで与えられたツールの範囲で決まります。

**コンテキストを管理する**
何をモデルに見せ、何を見せないかを決めます。
会話が長くなれば要約し、必要なファイルだけを読み込み、限られた入力枠に収まるよう調整します。
モデルの賢さが同じでも、判断材料が欠けていれば結論は変わります。

**安全性を担保する**
危険なコマンドを止める、書き込み先を制限する、実行前に人間に確認を取る。
モデルが間違えることを前提に、被害の範囲を設計します。

## なぜ区別する意味があるのか

同じモデルを使っていても、ハーネスが違えば結果は大きく変わります。

エージェントがうまく動かないとき、原因はモデルの能力不足とは限りません。
必要なファイルがコンテキストに入っていなかった、ツールの説明が曖昧で使い方を誤った、
エラーの内容がモデルまで届いていなかった。こうした問題はハーネス側にあります。

モデルは差し替えられますが、ハーネスは自分で設計するものです。
エージェントの性能を上げたいとき、手を入れられる余地は多くの場合こちら側にあります。

## 身近な例

Claude Code はハーネスの一例です。

Claude というモデルの周りに、ファイル操作ツール、コマンド実行、権限管理、コンテキスト圧縮、
サブエージェント、フック、といった仕組みが組まれています。
モデルを API で直接叩いただけでは、これらは何一つ付いてきません。

Cursor も、GitHub Copilot も、自作のエージェントスクリプトも、
それぞれ独自のハーネスを持っています。中で動くモデルは同じでも、使い勝手が違うのはそのためです。

## まとめ

ハーネスとは、モデルを道具として使えるようにする実行環境のことです。

モデルは判断する。ハーネスは、判断させるための材料を揃え、判断の結果を実行し、その結果をまた返す。
エージェントの振る舞いは、この二つの組み合わせで決まります。
